---Создание

- Создание репозитория и соединение с github
git init
git add .
git commit -m ‘name’ 
git branch -M main
git remote add origin <repo_path>

- Решить проблему разных имен веток
git branch -m master main
git fetch origin
git branch -u origin/main main
git pull origin main --allow-unrelated-histories
git push origin main
git push origin --delete master


- Создание репозитория
	1. С помощью cd переходим в нужный дир
	2. git init (создает пустой репозиторий)
	3. git config --global user.name "Your Name" (Настройка имени пользователя (глобально))
	4. git config --global user.email "your.email@example.com" (Настройка email пользователя (глобально))
	5. Готово!
	
	
- Клонирование удалённого репозитория
	1. С помощью cd переходим в нужный дир
	2. git clone URL
		где URL - путь к репозиторию git


- Добавление удалённого репозитория (связывание папки и репозитория) 
	1. git remote add origin <url>


- Частичное клонирование репозитория
1. git clone –filter=blob:none –no-checkout <repo_url>
2. cd в папку репозитория
3. git sparse-checkout init –cone (включает режим sparse checkout) 
4. git sparse-checkout set <путь_к_папке_в_репо/файл> (можно выбрать папку, файл, или несколько через пробел) 
5. git sparse-checkout list (список частичной загрузки) 


--- Проверки и Данные	

- Просмотр структуры репозитория
           git ls-tree -r HEAD –name-only

	
- Проверка удалённых репозиториев 
	git remote -v


- Просмотр настроек репозитория
	1. git config --list
	

- Узнать статус репозитория
	1. git status (в дире)
	

Отключение автозамены строк
1. git config –global core.autocrlf false



- Данные о коммитах репозитория
	1. git log PARAM (в дире)
		где PARAM
			-p <файл> - детализация коммитов для конкретного файла

	
	
--- Добавление, Перемещение, Удаление

- Добавить файл в staged (без коммита)
	1. ПОмещаем файл в дир git (git увидит неотслеживаемый файл)
	2. git add NAME
		где	NAME - имя добавляемого файла (с расширением) или подкаталога "path/" (со всем содержимым)
		(если указать "git add ." - добавит все измененные и отслеживаемые файлы в текущей дир)
	3. Теперь файл отслеживается но не добавлен в ветку (локален)
	
	
- Коммит добавленных изменений
	1. git commit [PARAMS]
		где [PARAMS] - параметры коммита:
			-m "message" - сообщение message к коммиту
			-a -m "message" - коммит сразу всех ОТСЛЕЖИВАЕМЫХ файлов (избегая выполнения add для каждого) с сообщением message к коммиту
			--allow-empty -m "message" - пустой коммит с message (для возможного отслеживания этапов)
			--amend - заменяет последний коммит текущим, заменяя новымы staged файлами и новым сообщением (не рекомендуется использовать после push - можно поломать русло проекта)


- Детализация данных о коммите
	1. git show <commit_hash>


- Детализация коммитов о файле
	1. git blame PARAMS <файл> [<начальный_хэш>..<конечный_хэш>]
		где
			<начальный_хэш>..<конечный_хэш> - диапазон коммитов (опционально)
		где PARAMS
			-w - игнорирование изменений связанных с пробелами
			-L <start>,<end> - анализ диапазона строк файла
			--show-name - Выводит только имя автора для каждой строки


- Снять файл со staged (снимет с индекса но файл останется)
	1. git reset <file>
	
	
- Удалить файл из репозитория и директории
	1. git rm <file>

	
- Удалить файл из отслеживания Git (снимет с индекса но файл останется)
	1. git rm --cached <file>

	
- Отмена изменений в файле (Возврат на актуальную версию)
	1. git restore <file>
		

- Полный сброс всех изменений в рабочем каталоге и индексе
	1. git reset PARAMS
		где
			--soft - откатывает коммит (возвращая все как до отправки коммита, сохраняя staged файлы)
			--hard - приводит все к последнему коммиту, удаляя staged файлы
			HEAD~n - количество откатов, где n = 1 - предыдущий коммит, 2 - два коммита назад и т.д.
	
	
- Работа с удаленным репозиторием
	1. git push [PARAMS] [repo] [branch]  (Отправка изменений на сервер) (для github нужна аутентификация или токены)
		где PARAMS
			--all - отправка всех веток в репозиторий
			--tags - отправка тэгов
			--delete <branch_name> - удаление ветки
			--force - перезаписывает изменения в удалённом репозитории (с возможной потерей данных)
			--force-with-lease - перезаписывает, но сначала проверяет были ли изменения
			--mirror <repo> - отправляет всё из локального репозитория в удалённый
			--dry-run - Показывает, что будет отправлено, без реальной передачи данных
			
	1. git pull (Получение изменений с сервера)
	1. git fetch (Обновление информации об удалённых ветках)


- Перемещение файла
	1. git mv <старое_имя> <новый_путь/новое_имя>
		где
			<старое_имя> - изначальный файл
			<новый_путь/новое_имя> - новый путь и/или новое имя файла

--- Черновики

- Просмотр черновиков
	1. git stash list


- Создание черновика
	1. git stash PARAM (созранит изменения в refs/stash, а текущие данные откатит до актуального коммита)
		где PARAM
			без параметра - стандартный stash
			-u - добавит в stash так же и untracked files
			save "Описание" - добавит описание
	

- Возврат из черновика
	1. git stash apply PARAM (возвращает данные из черновика (stash сохраняется, позволяя переиспользоваться))
		где PARAM
			без параметра - стандартный stash (взятие последнего в стеке)
			stash@{N} - берет stash под номером N

	ИЛИ
	1. git stash pop (возврат и удаление из stash)


- Очистка черновиков
	1. git stash clear
	
	
- Удаление черновика
	1. git stash drop PARAM
		где PARAM
			без параметра - стандартный stash (взятие последнего в стеке)
			stash@{N} - удаляет stash под номером N


--- Тэги

- Создание тэга
	1. git tag <name> (обычный тэг)
	или
	1. git tag -a <name> [commit-hash] -m "Описание" (аннотированный тэг)
		где
			<name> - имя тэга
			[commit-hash] - тэг на определенный коммит (опционально)


- Просмотр тэга
	1. git show <name> 
	
	
- Удаление тегов
	1. git tag -d <name> (локально)
	или
	1. git push origin --delete <name> (на удалённом репозитории)
	
- Отправка тегов на удалённый репозиторий
	1. git push origin --tags - отправка всех тэгов
	или
	1. git push origin <name> - отправка конкретного тэга
